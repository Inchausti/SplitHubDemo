01Objetivo e premissas

Subir o Gerador de massa de dados como um projeto estruturado — repositório, banco, CI, hospedagem e login — usando só planos gratuitos, e deixar o passo a passo para quem for montar.

PremissaO que significa
Custo zeroTodos os serviços em plano gratuito, sem cartão de crédito no cadastro.
Sair do free sem retrabalhoO app roda em Docker e lê a configuração de variáveis de ambiente. Trocar de plano ou de provedor não muda o código.
Decisões da propostaAssume a D-01 (TypeScript e PostgreSQL) e a D-02 (app hospedado, com acesso restrito ao time).
Nunca produçãoA trava de domínios vale também no servidor, por variável de ambiente, acima do que for cadastrado na tela.

03Limites e como o projeto convive com eles

O banco guarda estado, ids no destino, gabarito resumido e o corpo só das requisições com falha ou divergência; as de sucesso guardam o resumo. Retenção de 15 dias para os corpos.

05Banco de dados

PostgreSQL 17. Os dados das entidades ficam em colunas JSON, porque o app é genérico e não sabe de antemão os campos de cada domínio.

TabelaO que guarda

Cabe em 0,5 GB

Uma execução de 20.000 documentos gera cerca de 20.000 linhas em registros e outras tantas em requisicoes, sem corpos — poucos megabytes. É o corpo de cada chamada que pesa, e ele só é guardado quando há falha ou divergência.

Passo 5Criar o banco: esquema e migraçõesDev

As tabelas da seção 05 em packages/db/src/schema.ts. A partição mensal de requisicoes vai numa migração em SQL escrita à mão. O cofre cifra as credenciais com a chave mestra.

import { defineConfig } from 'drizzle-kit';

export default defineConfig({
  schema: './src/schema.ts',
  out: './migrations',
  dialect: 'postgresql',
  dbCredentials: { url: process.env.DATABASE_URL! },
});
pnpm --filter @massa/db exec drizzle-kit generate   # cria a migração a partir do schema.ts
pnpm --filter @massa/db exec drizzle-kit migrate    # aplica no banco do .env
// packages/core/src/cofre.ts — AES-256-GCM com a chave mestra
import { createCipheriv, createDecipheriv, randomBytes } from 'node:crypto';

const chave = Buffer.from(process.env.MASTER_KEY!, 'base64');   // 32 bytes

export function cifrar(texto: string) {
  const iv = randomBytes(12);
  const c = createCipheriv('aes-256-gcm', chave, iv);
  const dado = Buffer.concat([c.update(texto, 'utf8'), c.final()]);
  return { iv, dado, tag: c.getAuthTag() };
}

export function decifrar({ iv, dado, tag }: { iv: Buffer; dado: Buffer; tag: Buffer }) {
  const d = createDecipheriv('aes-256-gcm', chave, iv);
  d.setAuthTag(tag);
  return Buffer.concat([d.update(dado), d.final()]).toString('utf8');
}
Pronto quando: as tabelas existem no banco local, e um teste cifra e decifra um segredo.

Passo 12Monitor e backupTech lead

Backup semanal pelo Actions, guardado como artefato por 30 dias. Cadastrar a string direta do Neon em Settings → Secrets → Actions como NEON_DATABASE_URL.

# .github/workflows/backup.yml
name: backup
on:
  schedule:
    - cron: "0 6 * * 1"            # segunda, 03:00 em Brasília
  workflow_dispatch:

jobs:
  copiar-banco:
    runs-on: ubuntu-latest
    steps:
      - run: docker run --rm postgres:17 pg_dump "$DATABASE_URL" --format=custom > massa-$(date +%F).dump
        env:
          DATABASE_URL: ${{ secrets.NEON_DATABASE_URL }}   # string direta, sem pooler
      - uses: actions/upload-artifact@v4
        with:
          name: backup-banco
          path: "*.dump"
          retention-days: 30

09Decisões para aprovar
INF-01Onde hospedar sem custo

Recomendação: Render Free para o app e Neon Free para o banco, ambos na região da Virgínia (EUA), comum aos dois. Alternativas: uma VM do Oracle Cloud Always Free — mais capacidade e sem dormir, mas pede cartão para o cadastro e administração do servidor —, ou uma máquina do time com Cloudflare Tunnel, que depende da máquina ligada. Os dados são fictícios, então a região fora do Brasil não traz questão de LGPD.

INF-02Login

Recomendação: GitHub, liberado só para o time da organização (OAuth App, gratuito). O time já está no GitHub, e não há outro provedor de identidade a configurar.

INF-03Execução dos envios

Recomendação: No mesmo processo do servidor enquanto o app estiver no free, com o progresso gravado no banco para retomar depois de um reinício. Worker separado quando houver plano pago — o código já fica isolado no pacote engine.

INF-04O que o banco guarda

Recomendação: A semente, não a massa. Mesmo cenário e mesma semente regeneram a massa (RF-GMD-405), então o banco guarda só estado, ids no destino e o corpo das requisições com problema. No free, a retenção dos corpos cai de 90 para 15 dias (ajusta a D-08 da proposta).

INF-05Manter o serviço acordado

Recomendação: Começar aceitando o cerca de 1 minuto para acordar; ligar o UptimeRobot a cada 5 minutos só se os webhooks sofrerem. Um serviço ligado o mês todo usa cerca de 730 das 750 horas gratuitas; conferir os termos do Render antes.

INF-06Banco e migrações

Recomendação: PostgreSQL 17 com Drizzle: esquema em TypeScript, migrações em SQL versionadas no repositório e aplicadas na subida do servidor.
